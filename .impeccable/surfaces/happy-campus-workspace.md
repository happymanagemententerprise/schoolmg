# Happy Campus workspace

MODE Operate

## User-pinned direction

Use the dashboard screenshot supplied by the user as the layout and information-hierarchy reference: a persistent dark navigation rail, a clear top bar, a light analytics workspace, compact summary cards, and charts or tables beneath. Keep Happy Management's existing brand mark and palette; the reference does not authorize copying another product's name, logo, copy, or sample metrics.

## Purpose and scope

Redesign shared navigation, page structure, dashboards, forms, tables, and responsive behavior across SaaS owners, school administrators, teachers, students, parents, security guards, and hostel supervisors. Preserve working role-specific tasks and access boundaries.

## First screen

- Keep the current user's role and page visible in the shell.
- Put that role's next useful task or relevant school alert before trend summaries.
- School administrators see the task queue and upcoming dates before metrics and attendance analytics.
- Teachers see score entry and due work first; students see assignments and mentor support; parents see school updates and linked-child progress; SaaS owners see school onboarding and portfolio counts.
- Use real data where connected. Label demo values as local sample data and retain the existing demo banner.

## Composition

Keep a persistent dark sidebar on larger screens and an accessible slide-in menu on phones. Use a compact top bar for page identity and account actions. Give the work area a quiet light ground with white, thin-bordered data surfaces; use the existing dark navy, school green, coral, and brass palette for navigation, selection, and meaningful states. Keep common dashboard cards compact and reserve the strongest contrast for the most actionable summary or alert.

## Signature interaction

Surface a changed or urgent task in place in the relevant role's queue, keeping its state and next action readable without navigating to a separate report.

## Boundaries

- Campus Safety appears for school administrators and security guards. Hostel supervisors retain a separately named Hostel register.
- The parent guardian-badges panel is removed.
- Do not promise working push alerts until the site's server-side push configuration is present.
- The active-school switch is not yet exposed in the app; do not imply the interface completes multi-school switching.
- Keep all existing role-scoped data behavior and accessible keyboard/focus states.
